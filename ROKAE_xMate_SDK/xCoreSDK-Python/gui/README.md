# ROKAE xMate 机器人可视化控制面板 (PySide6)

A native desktop GUI for the ROKAE xMate ER7 Pro robot, built on top
of the official `xCoreSDK-Python` v0.7.1.

当前现场机器人识别为 ROKAE `xMate ER7Pro-M`，型号代码 `XME7p-R850`，
序列号 `X600UW0092`，出厂日期 `2026.7`。铭牌上的 AC230V、1000W、7kg、
850mm 等信息用于设备识别和安全核对，不作为 DexHand RS485 参数或控制器菜单项的来源。

![PySide6](https://img.shields.io/badge/PySide6-6.11-green) ![SDK](https://img.shields.io/badge/xCoreSDK-0.7.1-blue)

## Features

| Tab | Capability |
|-----|------------|
| 机器人连接 | IP 输入、连接/断开、自动适配机型 |
| 实时状态 | 上下电/操作模式/运行状态/SDK 版本/机器人信息 |
| **关节控制 (J1–J7)** | 7 个滑块 + SpinBox（°），点击 *MoveAbsJ* 一键到位；另含「用当前关节填充」「全部归零」 |
| **Jog 增量运动** | J1− / J1+ ... J7− / J7+ 按钮，每步增量可调（默认 5°），相对当前位置 +δ / −δ 运动（不容易出错） |
| **笛卡尔控制** | X/Y/Z + Rx/Ry/Rz 输入框，点击 *MoveL* 直线运动 |
| **末端按键** | 实时显示 key1 ~ key7 的 ON/OFF 状态 |
| **DexHand021 S 三指灵巧手** | USB 转 485 直连；机器人末端模式通过 xCore SDK `XPRS485SendData` 裸透传；P1/P2/P3/R 四轴控制、角度/Hall/力矩、压力/触觉、诊断保护、寄存器工具、动作序列 |
| 日志 | 所有 SDK 调用结果带时间戳；可选显示 485 收发帧、期望长度、实际回复和 xPanel 返回码 |

主窗口可直接拖动边框调整大小，默认 1280×900、最小 820×600；窗口变小时各功能页会自动出现滚动条，
不会因为固定控件宽度导致 P3、R 或发送按钮被挤出可视区域。
DexHand 页面中的“轴控制、状态监测、高级设置与寄存器、动作序列”也分别独立滚动；
串口设备列表显示当前设备摘要，鼠标悬停可查看完整列表，避免长文本把页面撑出横向滚动条。
程序还带单实例锁：同一台电脑只允许一个控制界面运行，避免多个窗口同时抢占半双工 485 总线。

## 安全机制（修复「一直往正方向移动」类问题）

1. **运动前确认对话框** — 弹出 J1..J7 的「当前 → 目标」对照表，默认 No（防止误点）
2. **运动幅度安全阈值** — 任何关节 Δ>170° 直接拒绝并提示「先点用当前关节填充」
3. **运动后自动同步** — MoveAbsJ/MoveL/jog 完成后，**强制把滑块、SpinBox、笛卡尔框重新同步到机器人实际姿态**（杜绝「以为没动就再按一次 → 累积漂移」）
4. **急停检查** — `setPowerState` 失败（-3 急停）时 `_ensure_powered_and_mode` 抛 SDKError，运动命令**不会**入队
5. **滑块软限位** — `JointSlider` 默认 ±170°，`set_value_deg` 自动 clamp 到软限位
6. **Jog 模式** — 永远相对当前 +δ，不会因为「拖错轴」造成大范围移动

## DexHand021 S 接线与使用

界面中的 **DexHand021 S 三指灵巧手** 页支持两种传输方式。两种方式都使用
说明书 V1.7 第六章的 Modbus RTU 裸帧：115200、8N1，CRC16-Modbus，
控制功能码为 `0x31`，状态读取功能码为 `0x04`。

要区分 Modbus 功能码和 0x31 帧内的模式字段：C++ SDK 对外的
`MotorControlMode` 枚举值为 `0x44/0x55/0x66`，SDK 发出 RTU 控制帧时会将
它们编码为 `Motor_Mode=0x04/0x05/0x06`。因此界面/API 仍使用 SDK 枚举值，
线上帧严格使用 SDK 的 `0x31 + Motor_Mode` 编码；这里的 `0x04/0x05/0x06`
不是读写请求的功能码。

### USB 转 485 直连电脑

1. 给 DexHand021 S 提供符合说明书要求的 24 V 电源。
2. USB 转 485 的 A/B/GND 接到灵巧手对应的 485 A/B/GND，USB 插入电脑。
3. 在界面选择“USB 转 485（电脑直连）”，填写系统分配的串口（当前 CH340 为 `COM7`），
   设备 ID 默认是 `1`；如果实际 ID 不同，按灵巧手当前 ID 修改。
4. 点击“连接灵巧手”。程序会先打开串口，再以只读方式探测 P1~P3；只有收到有效回复后才会显示“已连接”。
   读请求丢帧会安全重试；仅在连接阶段必要时自动重开 CH340，不会在运行中
   因状态读取失败擅自关闭串口或切断供电。该模式不要求机器人已经连接。
5. 默认控制模式为随附 C++ SDK 示例使用的 `0x55` 带限制 Hall 位置模式，速度控制量为 `1000`。
   界面和动作序列使用 C++ SDK 的 `MotorControlMode` 值 `0x44/0x55/0x66`，
   发送时由 SDK 规则映射到 0x31 帧内的 `Motor_Mode=0x04/0x05/0x06`；连接后默认只发送官方非阻塞 `clearFirmwareError()`，不会自动驱动机械手复位；
   每次运动前也会先清除锁存保护。控制页的“官方复位初始化”按钮才会执行
   `clearFirmwareError()` → `resetJoints()` → `clearFirmwareError()`，其中
   `resetJoints()` 会驱动 P1/P2/P3 到 Hall=0、R 到 280，必须先确认机械手周围安全。

### 接到珞石 xMate ER7Pro-M（XME7p-R850）机器人末端 485

1. 将灵巧手 485 A/B 接到珞石机器人实际末端工具接口的 RS485 A/B；将电源地
   共地。请以该 ER7Pro-M 现场接口定义和针脚标识为准，确认 A/B 极性。
2. 在主窗口先连接机器人控制器（电脑网线连接机器人控制器），再进入灵巧手页。
3. 不要按其它珞石机型的教程寻找“输出24V”“通信 → xPanel 设置”等菜单项。
   本程序不写入 ER7Pro-M 的末端工具或供电配置；以控制器当前实际显示的末端工具
   配置和控制器日志为准。灵巧手设备 ID=1、固定通信参数为 115200、8N1。
4. 主窗口连接机器人后，灵巧手页选择“机器人末端 485（珞石控制器透传）”，
   再点击“连接灵巧手”。程序不创建、上传或运行 RL 工程，不依赖工程变量和
   `Print` 回传；每一笔请求直接调用 xCore SDK 的
   `XPRS485SendData(send_byte, rev_byte, send_data, rev_data, ec)`。
5. `XPRS485SendData` 只负责按指定长度进行裸字节收发，程序再按 DexHand 说明书
   校验设备 ID、功能码、长度和 Modbus CRC。电脑不打开 COM 口，也不调用
   `XPRS485Init`。

### 其它支持 xPanel 裸 RTU 的珞石机型

对确实支持 `setxPanelRS485()`/`XPRS485SendData()` 的机型，程序使用官方
xPanel SDK 传输层；ER7 Pro 也只尝试其 SDK 实际暴露的 `XPRS485SendData`，不生成 RL 工程。
两种路径都不会把机器人末端口当成本机
COM 口，也不能把电脑 USB 转 485 同时接到同一条总线上。

485 是半双工总线。USB 直连和机器人末端连接是两种互斥的物理拓扑，不能同时把
两个主站接到同一条 485 总线上；切换接线前先断开灵巧手。

### xPanel、设备 ID 与通信参数确认

* 对当前 xMate ER7Pro-M（XME7p-R850），不要假定控制器存在“输出24V”或“通信 →
  xPanel 设置”等其它机型菜单。Python 程序不写入末端工具/供电配置，也不生成 RL
  工程；《末端透传使用手册》中的 `XPRS485RWData` 是 RL 语言指令，不是当前 xCore
  Python/C++ SDK 方法。程序使用 SDK 实际暴露的 `XPRS485SendData`。
* 灵巧手设备 ID 在 DexHand 页顶部“设备 ID”框中设置，默认是 `1`。连接成功后进入
  “高级设置与寄存器 → 设备信息与维护 → 读取设备信息”，返回的“设备 ID”才是设备
  实际 ID；日志会同时打印“设备返回 ID”和“界面当前目标 ID”，两者不同会给出警告。
* `115200、8N1` 是 DexHand021 S 的 Modbus RTU 固定通信参数：115200 波特率、8 数据位、
  无校验、1 停止位。它不是 xPanel 页的可读回参数；程序连接日志会打印完整协议参数，
  USB 模式也会打印实际打开的 COM 口和串口参数。
* DexHand 页连接区的“详细通信日志（记录 485 请求/回复帧）”默认开启。开启后，
  “日志”页会显示 `TX` 请求帧、期望回复长度、`RX` 实际回复帧、SDK `ec` 返回码、
  CRC/设备 ID/功能码校验失败原因；排查完成后可关闭，避免状态轮询产生大量日志。

### 控制范围

* `P1/P2/P3` 对应三个手指，`R` 对应说明书定义的旋转关节（轴 ID `0x04`）。
* 角度位置模式（C++ SDK `CASCADED_PID_CONTROL_MODE = 0x44`）：目标值为角度×10；P1/P2/P3 范围 0~750（0~75°），R 范围 0~1600（0~160°）。
* 带限制霍尔位置模式（C++ SDK `HALL_POSLIMIT_CONTROL_MODE = 0x55`）：P1/P2/P3/R 目标 Hall 0~1000，速度控制量 0~32767。
* 级联 MIT 力矩模式（C++ SDK `CASCADED_MIT_CONTROL_MODE = 0x66`）：P1/P2/P3 目标角度×10 范围 0~750，R 目标 0~1600，控制量 200~800。
* 状态页显示四轴角度、Hall、速度、电流、扭矩 PWM、温度和电压；部分固件不提供 R 轴状态寄存器时，R 行会显示“不可读”，但不会影响 P1~P3 轮询和 R 轴控制；P1~P3 可选读取法向/切向力、变化值、方向和接近觉；还可选读取最大扭矩、电流、速度、保护温度和堵转参数。
* 高级页支持反馈模式、最大输出电流、舵机保护温度、设备信息、清错、重启、0x03/0x04 读取和 0x06 单寄存器写入。
* 021S 的全局命令帧按 RTU 手册编码为 `设备ID 25 命令 电机ID 有效长度 数据0 数据1 CRC`，
  数据槽位固定发送 4 个字节。清错命令为 `25 A4 00 00 00 00 00`（含 CRC），
  对应官方 C++ SDK 的非阻塞 `clearFirmwareError()`；
  清错和重启通过末端 SDK 透传时都请求并校验 6 字节 `0x25` 确认；“非阻塞”仅指
  固件不等待内部清错/重启流程完成。重启期间会暂停状态轮询，避免把设备复位窗口误报为通信超时。
* 动作序列页支持记录 P1/P2/P3/R 当前目标、删除/清空、JSON 保存/加载和回放。
  回放会先发送当前步骤，轮询可读轴反馈确认动作完成，之后才开始该步骤的
  “完成后延时”；连续 3 次反馈稳定后进入下一步。0x44 按角度和速度判断，
  0x55 按 Hall 目标、0x44/0x66 按角度目标和速度判断；R 轴状态寄存器不可读时不会把序列永久卡住；
  单步等待超过 30 秒会停止并提示检查堵转、限位或通信状态。
* 单轴、三指快捷动作和“发送全部”会先等待约 1.2 秒，再持续回读实际位置、速度和电流，
  直到目标连续稳定到位；等待超过 30 秒才提示检查保护状态、机械限位、堵转和供电。
  到位检查只读取状态，不会自动重复发送运动帧。

### P3 轴控制

P3 在本界面中显示为“P3（手指3）”，不是隐藏在三指快捷按钮中。可以单独拖动
P3 滑块并点击“发送”，也可以在“发送全部当前目标”和“动作序列”中与 P1、P2、
R 一起控制。三指张开/闭合快捷按钮只发送 P1~P3，不会改变 R 旋转轴。

### 故障排查

* “回复超时”：截图中的 `01 04 00 00 00 03 b0 0b` 是合法的 P1~P3 只读探测帧；先关闭其他 GUI/串口工具，确认任务管理器中没有第二个 `robot_control_gui.py` 占用 COM7；再检查 24 V、电源地、A/B 极性、设备 ID 和 115200 波特率。日志会同时显示实际请求帧，并给出硬件检查清单。
  如果任务管理器里已经有旧窗口，先全部关闭再启动新版本；新版本会阻止第二个窗口启动。
* 如果设备返回 Modbus 异常帧，程序会显示异常码和完整回复帧。`0x01/0x02/0x03/0x04` 分别表示非法功能、非法地址、非法数据值、设备执行失败；这比“收到 5 字节”更适合判断寄存器地址或设备状态问题。
* 如果“打开串口成功但收到 0 字节”，说明电脑能看到 CH340，但灵巧手没有在该总线上应答；这通常不是窗口或滑块问题，优先检查独立 24 V、A/B/GND、485 收发器方向和设备 ID。
* “设备 ID 不匹配”：设备 ID 不是自动发现的，需在界面填入正确 ID。
* “电机控制被拒绝，错误标志 `0x08`”：根据随 SDK 提供的 `MotorErrorCode_21S`，这是
  `MOT_BLOCK`（电机堵转/运动受阻）。先停止发送动作，检查机械限位、夹持物、连杆/线缆、目标值和供电；
  排除阻挡后点击“清除错误”，再用较小目标进行单轴测试。程序不会自动重发该动作，避免堵转时继续加力。
* 机器人末端模式提示未连接：先在主窗口连接珞石控制器。
* xMate ER7Pro-M 机器人末端模式若日志出现 `XPRS485SendData` 错误码 `-1`，说明
  当前控制器/固件拒绝 SDK 直连末端透传；确认末端 A/B/GND、末端工具供电和设备 ID，
  并向珞石索取支持该机型的直接末端 485 SDK 接口。当前路径不生成 RL 工程，也不应
  出现 COM7 打开错误。

### 末端透传帧长度规则

机器人末端模式使用 xCore SDK 的：
`XPRS485SendData(send_byte, rev_byte, send_data, rev_data, ec)`：

* `send_byte` 必须等于 `send_data` 的实际长度；单次发送和接收均限制为 0~16
  字节。Python 绑定使用空的 `PyTypeVectorInt` 作为 `rev_data` 输出容器，
  由 `rev_byte` 指定期望长度；不在 Python 中声明 RL 工程变量。
* 021S 的 Modbus RTU 帧由程序按 DexHand 说明书生成并带上 CRC；透传接口不会
  自动补 CRC，也不会把 021S 的 `0x31` 电机控制帧改成通用 Modbus 寄存器帧。
* SDK 返回 `ec` 和 `rev_data` 后，程序进行长度、设备 ID、功能码和 CRC 校验。

## 安全特性

1. **自动检测机型** — connect 时按 `xMateErProRobot` → `xMateRobot` → ...
   顺序试探，避开 *机器人实例类型与连接的机型不符* 错误。
2. **运动前自动上电/切自动模式** — 点击运动按钮时自动 `setPowerState(True)` + `setOperateMode(automatic)`。
3. **阻塞等待** — `MoveAbsJ` / `MoveL` 后会等到 `OperationState.idle` 才返回（最长 30s），保证运动完成再退出回调。
4. **异常捕获** — 所有 SDK 调用通过 `ec` dict 检查，错误显示在日志面板，不抛出未处理异常。
5. **窗口关闭自动断开** — `closeEvent` 中调用 `disconnect()`。

## 实现细节
